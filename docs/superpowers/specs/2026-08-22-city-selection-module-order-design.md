# 城市选择与主页模块排序设计

## 目标

为天气模块提供手动城市搜索与一键回到当前位置；允许在展开的灵动岛内使用 `Command + 长按拖动` 调整播放器、待办、日历和天气的横向顺序。

## 范围

- 天气卡底部改为“切换城市”和“当前位置”两个入口。
- 手动选择城市或区县后，立即显示其天气，并在下次启动后保持该选择。
- 点击“当前位置”后清除手动选择，使用系统定位并立即刷新。
- 可见主页模块按保存的顺序横向排列；每个模块保持自己的现有宽度，灵动岛整体尺寸不变。
- 在“设置 → 高级”增加排序操作说明。

不包含未来天气、任意像素位置、上下移动、模块重叠、空白占位或新天气服务商。

## 天气位置来源

新增可编码的位置选择模型：

- `automatic`：使用 Core Location 当前坐标。
- `manual`：保存 MapKit 搜索结果的显示名称、纬度与经度。

该模型保存在 Defaults。天气管理器在手动模式下绕过定位请求，直接使用保存坐标获取天气；在当前位置模式下删除手动选择、失效天气缓存并请求最高可用精度的当前坐标。

### 搜索与选择

“切换城市”打开锚定天气卡的紧凑浮窗：

1. 输入框支持城市、区县和完整地址，例如“路南区”或“唐山市路南区”。
2. 使用 MapKit 地址搜索和联想结果，结果显示主名称与行政区副标题。
3. 选择结果后保存坐标与名称、关闭浮窗并立即刷新天气。
4. 搜索为空、无结果或网络失败时，浮窗显示中文提示，不覆盖当前已显示的天气。

“当前位置”按钮在自动模式时显示蓝色；手动模式时“切换城市”显示蓝色。两种模式互斥。

### 数据来源署名

天气卡底部不再显示 “Open-Meteo”。由于数据许可需要来源链接，在城市名称旁保留一个很小的 `ⓘ` 信息入口；点击后显示“天气数据由 Open-Meteo 提供”及来源链接。这样两个底部位置完整留给城市操作，同时保留必要署名。

## 模块排序

新增 `HomeModule` 枚举，固定成员为：`player`、`todo`、`calendar`、`weather`。Defaults 保存完整排序，默认顺序保持当前行为：播放器、待办、日历、天气。

主页仅从已启用模块中生成显示队列；关闭某模块不删除其排序位置，重新开启后回到原保存位置。分隔线只出现在相邻的可见模块之间。

每种模块继续采用现有尺寸规则：播放器保持当前根据已启用侧栏数计算的宽度，待办、日历、天气保持各自既有宽度。排序仅改变顺序，不改变任意模块尺寸或灵动岛总宽度。

### 拖拽交互

- 必须先按住 `Command`，再在模块的非交互空白区域长按约 0.35 秒才能开始拖动。
- 拖动开始时，模块显示蓝色描边和轻微缩放；目标位置显示插入高亮。
- 拖过另一个模块前后半区时，模块立即平滑让位；松开后保存新排序。
- 不按 `Command` 时，模块内原有控件保留原行为，包括播放器进度条、待办输入框、日历按钮和天气按钮。
- 排序仅限单行横向吸附，不允许自由像素坐标、重叠、上下移动或空白槽位。

## 高级设置说明

在“设置 → 高级”增加如下静态说明：

> 主页模块排序
>
> 展开灵动岛后，按住 Command 键，再长按播放器、待办、日历或天气模块并横向拖动，即可交换位置。松开后顺序会自动保存。

## 验证

- 单元测试：位置模式切换、手动坐标持久化、自动定位回退、排序规范化、重排序、隐藏模块恢复原位置。
- 交互策略测试：只有 `Command + 长按` 可进入排序状态；普通点击不进入排序状态。
- UI 文案检查：天气卡不再显示底部 Open-Meteo 文本，两个城市按钮与高级设置说明均为中文。
- 构建、签名、DMG 校验、安装版本与运行进程验证。

## 约束

- 保持 Open-Meteo 作为现有无密钥天气数据源。
- 仅使用本机的 MapKit 和系统定位，不增加第三方密钥。
- 不提交或推送任何本地修改，除非用户另行授权。
